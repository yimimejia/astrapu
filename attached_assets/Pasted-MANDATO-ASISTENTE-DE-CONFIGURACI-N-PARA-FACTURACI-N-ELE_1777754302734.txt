MANDATO — ASISTENTE DE CONFIGURACIÓN PARA FACTURACIÓN ELECTRÓNICA DGII

Actúa como arquitecto senior full-stack especialista en facturación electrónica dominicana DGII, e-CF, e-NCF, certificado digital, XML firmado, Representación Impresa, contingencia fiscal, NCF, POS, sistemas administrativos y cumplimiento tributario.

Necesito implementar un ASISTENTE DE CONFIGURACIÓN DE FACTURACIÓN ELECTRÓNICA DGII que pueda ser utilizado en cualquier sistema.

NO amarres este módulo a una empresa específica.
NO escribas nombres de empresas quemados.
NO escribas nombres de aplicaciones quemados.
NO dependas de un solo tipo de negocio.
NO hagas una pantalla simple con campos sueltos.
NO hagas simulaciones falsas.
NO digas que DGII aceptó algo si no hubo respuesta real de DGII.
NO permitas activar producción si faltan requisitos.
NO permitas emitir e-CF si el asistente no está completado correctamente.
NO permitas duplicar e-NCF.
NO permitas editar XML firmado.
NO permitas borrar e-CF emitidos.
NO permitas mezclar configuración fiscal entre sucursales, empresas o entidades.

OBJETIVO GENERAL

Crear un asistente paso a paso que guíe al usuario para configurar la facturación electrónica DGII dentro del sistema.

El asistente debe permitir:

1. Registrar los datos fiscales del contribuyente.
2. Validar requisitos básicos para ser emisor electrónico.
3. Cargar y proteger el certificado digital.
4. Registrar la solicitud de emisor electrónico.
5. Configurar ambiente de pruebas.
6. Gestionar sets de pruebas.
7. Generar y validar Representación Impresa.
8. Registrar Declaración Jurada.
9. Registrar Certificación DGII.
10. Configurar rangos e-NCF.
11. Configurar ambiente de producción.
12. Activar o bloquear emisión electrónica según el estado real.
13. Emitir e-CF desde ventas, facturas o documentos del sistema.
14. Firmar XML digitalmente.
15. Enviar e-CF a DGII.
16. Consultar estado.
17. Manejar respuestas, rechazos y errores.
18. Manejar contingencia offline.
19. Reintentar envíos pendientes.
20. Recibir e-CF de proveedores.
21. Guardar auditoría fiscal completa.

PRINCIPIO DE DISEÑO

Este asistente debe ser reutilizable.

Debe funcionar para:
- Cualquier empresa.
- Cualquier sistema POS.
- Cualquier sistema administrativo.
- Cualquier sistema de facturación.
- Cualquier negocio con ventas.
- Cualquier negocio con servicios.
- Sistemas con una sola empresa.
- Sistemas multiempresa.
- Sistemas multisucursal.

No debe contener textos quemados como:
- Nombre de empresa específica.
- Nombre de aplicación específica.
- RNC específico.
- Logo específico.
- Endpoints quemados sin configuración.
- Certificado fijo.
- Secuencias e-NCF fijas.

Todo debe venir desde configuración.

COMPATIBILIDAD MULTIEMPRESA O MULTISUCURSAL

El módulo debe soportar tres escenarios:

1. Sistema de una sola empresa.
2. Sistema con varias sucursales.
3. Sistema multiempresa.

Por eso, toda configuración debe estar asociada a una entidad fiscal configurable.

Crear el concepto:

fiscal_entity

Una fiscal_entity puede representar:
- Una empresa
- Una sucursal
- Una razón social
- Una unidad fiscal independiente

Todas las configuraciones de DGII deben depender de fiscal_entity_id.

No asumir que todo el sistema tiene un solo RNC.

PASOS DEL ASISTENTE

PASO 1 — DATOS DEL CONTRIBUYENTE

Objetivo:
Capturar los datos fiscales básicos del emisor.

Campos:

- RNC
- Razón social
- Nombre comercial
- Dirección fiscal
- Provincia
- Municipio
- Teléfono
- Correo
- Tipo de contribuyente
- Actividad económica si aplica
- Nombre del representante
- Cédula del representante
- Cargo del representante
- Teléfono del representante
- Correo del representante

Checklist:

- Está inscrito en el RNC
- Tiene obligaciones tributarias activas
- Tiene clave de acceso a Oficina Virtual
- Está al día con sus obligaciones tributarias
- Tiene autorización para emitir comprobantes fiscales

Validaciones:

- RNC obligatorio
- Razón social obligatoria
- Dirección obligatoria
- Teléfono obligatorio
- Correo válido
- Representante obligatorio
- Cédula del representante obligatoria
- No permitir avanzar si faltan datos obligatorios

Acción automática:

Al guardar este paso, actualizar:

- ecf_settings.rnc
- ecf_settings.legal_name
- ecf_settings.commercial_name
- ecf_settings.address
- ecf_settings.province
- ecf_settings.municipality
- ecf_settings.phone
- ecf_settings.email
- ecf_settings.representative_name
- ecf_settings.representative_document
- fiscal_entity fiscal data
- estado del asistente

PASO 2 — VERIFICACIÓN DE REQUISITOS DGII

Objetivo:
Confirmar los requisitos antes de solicitar autorización como emisor electrónico.

Checklist:

- Inscripción en RNC confirmada
- Obligaciones tributarias confirmadas
- Acceso a Oficina Virtual confirmado
- Formulario de solicitud disponible
- Certificado digital disponible o en proceso
- Software preparado para emitir e-CF
- Software preparado para recibir e-CF
- Software preparado para Acuse de Recibo
- Software preparado para Aprobación Comercial
- Software preparado para Representación Impresa
- Cumplimiento de comprobantes fiscales

Campos:

- Fecha de revisión
- Responsable interno
- Observaciones
- Evidencia adjunta opcional

Acción automática:

Si todos los requisitos obligatorios están marcados, cambiar estado a:

requisitos_completados

Si faltan requisitos, cambiar estado a:

requisitos_incompletos

PASO 3 — CERTIFICADO DIGITAL

Objetivo:
Registrar y proteger el certificado digital para procesos tributarios.

Campos:

- Nombre del titular del certificado
- Cédula del titular
- Entidad certificadora
- Fecha de emisión
- Fecha de vencimiento
- Archivo del certificado
- Contraseña del certificado
- Confirmación de que corresponde al representante autorizado

Validaciones:

- Archivo obligatorio
- Contraseña obligatoria
- Fecha de vencimiento obligatoria
- No permitir certificado vencido
- Alertar si vence pronto
- No mostrar la contraseña después de guardada

Seguridad:

- Guardar contraseña cifrada
- Guardar archivo en ruta protegida
- No exponer certificado públicamente
- No enviar contraseña al frontend después de guardarla
- Registrar auditoría al cargar, reemplazar o eliminar certificado

Estados del certificado:

- no_cargado
- cargado
- valido
- vencido
- error
- por_vencer

Acciones:

- Subir certificado
- Validar certificado
- Reemplazar certificado
- Ver fecha de vencimiento
- Ver estado
- Probar firma local

PASO 4 — SOLICITUD DE EMISOR ELECTRÓNICO

Objetivo:
Registrar el proceso de solicitud ante DGII.

Campos:

- Fecha de solicitud
- Estado de solicitud
- Número de referencia si aplica
- Evidencia adjunta

- no_iniciada
- en_preparacion
- enviada
- en_revision

- rechazada
- requiere_correccion

Checklist:

- Datos del contribuyente completos
- Requisitos DGII completados
- Certificado digital registrado
- Formulario preparado
- Responsable confirmado

Acción automática:

Si la solicitud es marcada como aprobada para pruebas, cambiar estado general del asistente a:

aprobado_para_pruebas

PASO 5 — AMBIENTE DE PRUEBAS

Objetivo:
Configurar el entorno de pruebas para certificación DGII.

Campos:

- URL autenticación pruebas
- URL recepción e-CF pruebas
- URL aprobación comercial pruebas
- URL consulta estado pruebas
- Usuario o credencial si aplica
- Token si aplica
- Certificado seleccionado
- Ambiente activo: pruebas

Botones:

- Probar autenticación
- Probar certificado
- Probar firma digital
- Probar conexión
- Ver logs técnicos

Reglas:

- No permitir pruebas si no hay certificado válido
- No permitir pruebas si faltan URLs obligatorias
- No marcar como exitoso si no hubo respuesta real
- Si solo se valida internamente, mostrar “Prueba local exitosa”
- Si se comunica con DGII, guardar request, response, fecha y resultado

Objetivo:
Gestionar las pruebas requeridas para certificación.

Funciones:

- Crear set de prueba
- Subir archivo del set
- Registrar casos
- Generar XML por caso
- Firmar XML
- Enviar XML
- Consultar estado
- Guardar TrackID
- Guardar respuesta DGII
- Marcar aceptado
- Marcar rechazado
- Ver error
- Corregir y reenviar
- Adjuntar evidencia
- Ver porcentaje de avance

Estados por caso:

- pendiente
- generado
- firmado
- enviado
- aceptado
- rechazado
- corregido
- reenviado
- completado

Reglas:

- No permitir marcar caso como completado sin evidencia
- No permitir avanzar a Declaración Jurada si hay pruebas pendientes
- No permitir alterar XML aceptado
- Si se corrige un XML, crear nueva versión
- Guardar auditoría por cada intento

- Código de seguridad si aplica

- Guardar logs completos

Campos de la cola:

- Estado
- Fecha de emisión

- Intentos

- Próximo intento

Estados:

- pendiente_envio
- enviando
- enviado
- aceptado
- rechazado
- vencido
- error

Reglas:

- Para falta de conectividad, controlar plazo máximo de 72 horas
- No perder XML
- No perder factura
- No duplicar envío
- No reasignar e-NCF
- Registrar cada intento

FLUJO DE EMISIÓN DE e-CF

Cuando el sistema necesite emitir un e-CF:

1. Recibir documento origen: venta, factura, nota de crédito, nota de débito u otro.
2. Identificar fiscal_entity_id.
3. Validar que el asistente esté completado.
4. Validar producción activa o ambiente correcto.
5. Validar certificado vigente.
6. Validar rango e-NCF activo.
7. Reservar próximo e-NCF de forma transaccional.
8. Generar XML.
9. Firmar XML.
10. Guardar XML y XML firmado.
11. Enviar a DGII.
12. Guardar respuesta.
13. Consultar estado si aplica.
14. Cambiar estado del e-CF.
15. Generar Representación Impresa.
16. Asociar e-CF al documento origen.
17. Registrar auditoría.

VALIDACIONES CRÍTICAS

Antes de emitir:

- Debe existir fiscal_entity_id.
- Debe existir configuración fiscal completa.
- Debe existir certificado válido.
- Debe existir rango e-NCF activo.
- El asistente debe estar certificado/configurado.
- Si es producción, producción debe estar activa.
- El documento origen debe tener totales válidos.
- El e-NCF debe reservarse con bloqueo transaccional.
- No se puede emitir si hay configuración incompleta.
- No se puede emitir si el certificado está vencido.
- No se puede emitir si el rango está agotado.

- Historial de cambios

Textos importantes:

Si falta certificado:
“No puede continuar porque no hay certificado digital válido.”

Si faltan rangos:
“No puede emitir comprobantes electrónicos porque no existen rangos e-NCF activos.”

Si producción no está activa:
“El sistema está configurado, pero producción aún no está activa.”

Si DGII rechaza:
“El comprobante fue rechazado por DGII. Revise el detalle del error antes de reenviar.”

Si está en contingencia:
“El comprobante fue generado en contingencia y está pendiente de envío a DGII.”
